> **Статус:** согласован ✅ (решения от 12.08.2026 — см. раздел 10)
> **Создан:** 12.08.2026

---

## 1. Цель

Сделать собственного Telegram-бота ProektMap, который:

1. **Дублирует контент проекта в Telegram** — постит новости блога, новые разделы, еженедельную выжимку.
2. **Служит живым доказательством продукта** (dogfooding) — ProektMap учит «как сделать Telegram-бота», и наш бот это демонстрирует на практике. Для витрины это сильнее любого блог-поста.
3. **Удерживает аудиторию** — интерактив (AI-консультант, decision-coach, квиз) превращает канал в точку ежедневного возврата.

**Почему Telegram:** аудитория ProektMap — российские AI-инженеры/разработчики без VPN и зарубежных карт. Telegram — основной канал общения этой аудитории.

## 3. Функции подробно

### 3.1 Постинг новостей блога (Фаза 1) ✅ MVP

- **Источник:** `https://proektmap.ru/blog/rss.xml` (уже работает, 30 последних постов, поле `<guid>`).
- **Механизм:** бот опрашивает RSS раз в 15–30 минут, сравнивает `<guid>` с уже отправленными (state-файл), новые — публикует в канал.
- **Первый запуск:** только фиксирует baseline (не шлёт 30 старых постов).
- **Формат поста:**
  ```
  📰 {заголовок}
  {excerpt до 200 символов}
  Читать → https://proektmap.ru/blog/{slug}
  ```

### 3.2 Еженедельная выжимка «Что нового на проекте» (Фаза 1) ✅ MVP — фишка

- **Источник данных:** `git log --since="7 days ago" --oneline` + хвост `docs/DEVLOG.md`.
- **Генерация:** DeepSeek (`deepseek-chat`) превращает сырые коммиты/лог в человекочитаемую сводку из 3–6 пунктов: «что сделано нового и внедрено».
- **Расписание:** понедельник, 10:00 MSK (node-cron внутри бота).
- **Формат поста:**
  ```
  🗓 Итоги недели на ProektMap
  • Появилось: ...
  • Внедрили: ...
  • В работе: ...
  Подробнее → https://proektmap.ru
  ```
- **Контроль качества:** сводку сначала писать в служебный лог / отдельный чат админа, публиковать в канал только после одобрения (флаг `AUTO_APPROVE`).

### 3.3 AI-консультант в боте (Фаза 2)

- **Переиспользование:** та же логика, что в `/api/ai/ask` — DeepSeek, systemPrompt «AI-Архитектор» (объяснять простым языком, на русском, 2–4 предложения + совет).
- **Интерфейс:** команда `/ask <вопрос>` или любой текст в ЛС бота (fallback-обработчик).
- **Лимиты:** rate limit на пользователя (например, 20 вопросов/день), чтобы не жечь ключ бесплатно.

### 3.4 decision-coach (Фаза 2)

- Это запланированный Skill (спринт 12–25.08). Бот ведёт диалог по цепочке **ПОНЯТЬ → ВЫБРАТЬ → ПРОВЕРИТЬ → «Моё решение»**.
- Команда `/decide` — бот задаёт вопросы, в конце выдаёт заполненный decision brief и ссылку на Blueprint.
- Бот становится живой демкой этого скилла.

### 3.5 Навигатор по БД (Фаза 2)

Команды-карточки из Prisma (read-only):

| Команда | Что выдаёт | Таблица |
|---------|-----------|---------|
| `/blueprint <slug>` | карточка Blueprint (этапы, стек) | `Blueprint` |
| `/tool <название>` | карточка AI-инструмента | `AITool` |
| `/skill <название>` | карточка Skill + trust-статус | `Skill` |
| `/term <термин>` | определение из глоссария | `GlossaryTerm` |

### 3.6 Квиз (Фаза 2)

- 1 вопрос в день (из `Quest` / глоссария), варианты ответа — inline-кнопки.
- Правильный ответ + краткое пояснение → возвращаемость и вовлечение.

### 3.7 Постинг новых разделов (Фаза 3)

- Анонс при публикации нового Blueprint/Skill/раздела: заголовок + описание + ссылка.
- Триггер: ручной (команда админа) или авто по факту появления `status=published`.

### 3.8 Инлайн-режим и Mini App (Фаза 3, опционально)

- **Инлайн:** `@bot RAG` в любом чате → определение термина.
- **Mini App (WebApp):** витрина проектов / диагностика «какой Blueprint под мой проект» — внутри Telegram.

## 4. Архитектура и стек

```
proektmap.ru/
└── bot/                      ← отдельная папка, свой package.json
    ├── package.json          ← grammy + @grammyjs/runner + node-cron + tsx
    ├── tsconfig.json
    ├── .env                  ← TELEGRAM_BOT_TOKEN, TELEGRAM_CHANNEL_ID, DEEPSEEK_API_KEY
    ├── index.ts              ← точка входа, регистрация команд/обработчиков
    ├── src/
    │   ├── rss.ts            ← опрос блога (3.1)
    │   ├── digest.ts         ← еженедельная выжимка (3.2)
    │   ├── ai.ts             ← DeepSeek-клиент (общий для 3.2, 3.3, 3.4)
    │   ├── commands.ts       ← /start /help /ask /decide /blueprint /tool /skill /term
    │   ├── quiz.ts           ← квиз (3.6)
    │   └── db.ts             ← PrismaClient (read-only к той же БД)
    └── state/
        └── posted-guids.json ← дедуп RSS (3.1)
```

- **Стек:** Node + TypeScript + **grammy** (современная, лёгкая, TS-first). Тот же стек, что Next.js — один сервер.
- **БД:** тот же Prisma client → та же PostgreSQL (боту нужен только read-доступ к публичным данным).
- **AI:** DeepSeek `deepseek-chat` (ключ уже есть в проекте).
- **Расписания:** `node-cron` внутри процесса (RSS-опрос, выжимка, квиз).

## 6. Деплой

- **Процесс:** `pm2 start bot/index.ts --name proektmap-bot --interpreter node` (через `tsx`) — **отдельно** от `proektmap` (Next.js) и `leads-*`.
- **Автостарт:** `pm2 save` + `pm2 startup`.
- **Логи:** `pm2 logs proektmap-bot` + отдельный файл для выжимок (превью перед публикацией).
- **Билд Next.js не затрагивается** — бот живёт в своей папке, сайт не пересобираем при правках бота.

## 8. Критерии готовности

| Критерий | Проверка |
|----------|----------|
| Бот отвечает на `/start` `/help` | лично в Telegram |
| Новый пост блога появляется в канале ≤ 30 мин | опубликовать черновик → проверить канал |
| Выжимка приходит в понедельник и корректна | тестовый запуск вручную |
| `/ask` даёт осмысленный ответ | задать вопрос |
| Сайт не сломан, `proektmap` и `proektmap-bot` оба online | `pm2 status` |
| Токены не закоммичены | `.gitignore` содержит `bot/.env` |

## 9. Риски и ограничения

1. **Отдельный токен** — обязательно; конфликт с leads-ботом (он уже использует Telegram для уведомлений).
2. **Спам-лимиты Telegram** — не чаще 1–2 сообщений/день в канал; RSS-опрос не должен дублировать при рестарте (state-файл).
3. **LLM-галлюцинации в выжимке** — DeepSeek может переврать суть коммитов. При авто-публикации (`AUTO_APPROVE=true`) защита: строгий промпт «суммируй только переданные коммиты/лог, не выдумывай», ограничение длины и только факты из git/DEVLOG. При сбоях — деградация к простому списку коммитов без LLM.
4. **Бесплатный AI в боте** — rate limit на `/ask`, иначе ключ сожжётся.
5. **Read-only БД** — бот только читает публичные данные, ничего не пишет в production-таблицы.
