# Visual Factory v0.1 — план на 2 недели

> Рабочий план инициативы «ProektMap Visual Factory».
> Концепция и философия: `docs/PROEKTMAP-VISUAL-FACTORY.md` (раздел 28 там — канонический pipeline).
> Этот план — ЕДИНСТВЕННЫЙ источник того, ЧТО ДЕЛАТЬ в ближайшие 14 дней. Концепция отвечает на вопрос «почему и как устроено», план — «что делаем сейчас».

## 0. Definition of done (через 14 дней)

1. **5 Visual Solutions** опубликовано в `/resheniya` (минимум 3 — уровня «хочется сразу применить»).
2. У каждого: живой preview **desktop + mobile**, карточка по текущему шаблону `/resheniya`, `DESIGN.md`, агентский пакет (README + build.md + prompts + reference-скриншоты + QA-чеклист).
3. Весь процесс прошёл **5 раз** — трудоёмкость каждого этапа зафиксирована.
4. Измерены первые сигналы спроса: copy-prompt, скачивания пакетов, глубина просмотра.
5. Принято решение **Go / No-Go** по развитию (каталог компонентов, MCP, «Try with my content»).

Если после 2 недель нет 3 сильных решений — не строим дальше, а чиним процесс.

## 2. Первый набор доноров (5 направлений)

Принцип: 5 максимально разных визуальных языков, каждый покрывает типичный запрос аудитории. Куратор выбирает 1 из 2 кандидатов.

| # | Направление / Visual character | Доноры-кандидаты (референсы) | Новый проект (наш) |
|---|---|---|---|
| A | **Editorial Swiss** — строгая сетка, крупная типографика, много воздуха | big.dk (BIG) или победитель Awwwards, architecture | Лендинг стоматологической клиники |
| B | **Premium dark SaaS** — тёмный, точный, сдержанный motion | linear.app | Лендинг CRM / аналитики |
| C | **Product minimal light** — чистота, уверенная типографика, цветовой акцент | stripe.com или vercel.com | Лендинг онлайн-сервиса / API-стартапа |
| D | **Bold playful studio** — смелая типографика, цветовые блоки, заметная анимация | креативная студия из Awwwards/Godly (на выбор куратора) | Лендинг онлайн-школы (курсы по AI) |
| E | **Editorial media** — серифная иерархия, ритм длинного контента | kinfolk.com или editorial-победитель Awwwards | Контент-хаб / блог |

Правило отбора: если куратор не может одной фразой сказать, чем донор отличается от остальных четырёх — не берём.

## 3. Разделение труда

**Человек (куратор) — только вкус и решения:**
- выбор доноров, формулировка visual character;
- brief нового проекта (≈1 час на проект);
- ревью `DONOR ANALYSIS` и `DESIGN.md` (факт/интерпретация не смешаны?);
- визуальная приёмка desktop + mobile;
- проверка прав и происхождения;
- публикация, текст карточки.

**Агент (Cursor) — роли как последовательные задачи:**

| Роль | Вход | Выход | Критерий готовности |
|---|---|---|---|
| Donor Analyst | URL донора | `DONOR ANALYSIS` | Факты отделены от интерпретаций, «не знаю» помечено |
| Design Extractor | анализ | `DESIGN.md` | Без бренда/текстов/фото донора правила всё ещё понятны |
| Content Neutralizer | DESIGN.md | чистый DESIGN.md + список запрещённого к переносу | Ноль следов контента донора |
| Builder | DESIGN.md + brief | готовый сайт на demo-контенте | Открывается desktop+mobile, стиль соответствует DESIGN.md |
| Visual QA | сайт + DESIGN.md | отчёт PASS / NEEDS REFINEMENT + конкретные замечания | Каждое замечание — «что именно не так» |
| Packager | принятое решение | ZIP: README, DESIGN.md, build/refine/mobile промпты, reference, checklist | Пакет применим «вслепую» в Cursor |
| Publisher | решение + пакет | карточка `/resheniya` по текущему шаблону | Соответствует стилю существующих карточек |

Роли — последовательные задачи одного агента, не отдельные продукты. Каждая роль = файл-промпт в `/visual-factory/prompts/`.

## 6. Как измеряем результат

**Производство:**

| Метрика | Цель |
|---|---|
| Решений опубликовано | 5 (мин. 3 сильных) |
| «Донор → публикация» | ≤ 3 рабочих дня |
| QA-итераций на решение | ≤ 3 |
| Время куратора на решение | ≤ 3 часов |

**Спрос:**

| Метрика | Как мерить | Порог |
|---|---|---|
| Copy Prompt rate | клики «Копировать промпт» / посетители | ≥ 3% отлично; 1–3% интерес; < 1% тревога |
| Скачивания пакета | счётчик ZIP | ≥ 5 суммарно за неделю 2 |
| Глубина | доскролл до «что входит» + переключение Desktop/Mobile | ≥ 30% посетителей |
| Обратная связь | сообщения/комментарии | ≥ 1 — сильный сигнал |

**Go/No-Go (день 14):**
- **Go**: ≥ 3 сильных решения + copy rate ≥ 3% ИЛИ ≥ 5 скачиваний ИЛИ реальная обратная связь.
- **Pivot**: copy rate < 1% и 0 скачиваний — не строим каталог компонентов; переосмысливаем подачу.
- **Stop**: не вышло 3 сильных решения — чиним процесс.

## 7. Риски и страховки

| Риск | Страховка |
|---|---|
| Агент делает клон, а не решение | Builder-промпт начинается с манифеста (раздел 34 концепции); QA отдельно проверяет «не скопирован ли контент/ассеты» |
| Красиво, но одинаково (AI-slop) | 5 контрастных доноров; куратор в день 13 режет похожие |
| Публикация скриншотов донора — юр. риск | Публикуем только скриншоты наших сборок; донор и его скриншоты — только внутри `/visual-factory/donors` |
| Утонуть в полировке | Лимит: 3 итерации QA на решение, дальше куратор решает «принять с оговорками» или «архив» |
| Агент выдумывает факты о доноре | В `donor-analyst.md` поле «Уверенность: факт/гипотеза/не проверено» |
