# Готовые решения AI · продуктовый каркас v1

## Позиционирование

**Готовые решения AI** — центр ProektMap, который ведёт человека от цели до проверенного результата.

- Русское название: **Готовые решения AI**
- URL: **`/resheniya`**
- Внутреннее имя модели: **Solution Route**
- Пилот: **«Запустить SaaS-продукт»**
- Старые Blueprint продолжают работать независимо

## Обещание пользователю

> В любой момент понятно: что делать сейчас, какой результат должен появиться и как доказать его готовность.

## Единая модель

```text
Цель продукта
  → Этап
    → Решение
      → Действие
        → Артефакт
          → Проверка
            → Следующий этап
```

Прогресс продукта растёт только после проверенного результата. Чтение контента и XP не двигают проект к финишу.

## UX-структура

1. `/resheniya` — каталог результатов, а не курсов.
2. `/resheniya/saas-product` — контракт результата и полная карта.
3. `/resheniya/saas-product/workspace` — одна текущая миссия:
   - Понять;
   - Решить;
   - Сделать;
   - Проверить.
4. Паспорт проекта собирает решения и артефакты.
5. Связанные ветки ProektMap появляются в контексте текущего этапа.

## Перелинковка экосистемы

`/resheniya` является центром действия:

- Песочница — исследование идеи;
- Глоссарий — понятия текущей миссии;
- AI-модели — выбор модели;
- AI-инструменты — выполнение;
- Skills — навыки агента;
- Паттерны — архитектурные решения;
- Промпты — запуск работы;
- MCP — интеграции;
- Российский AI-стек — инфраструктура без VPN;
- AI Цех — реальные примеры.

Ссылки не выводятся общей свалкой: каждый этап показывает только релевантные ветки.

## Пилотный маршрут SaaS

1. Проверить проблему → `Problem Brief`
2. Ограничить MVP → `MVP Contract`
3. Собрать бизнес-модель → `Offer & Pricing`
4. Спроектировать опыт → `User Flow`
5. Спроектировать систему → `Architecture Pack`
6. Собрать рабочий срез → `Working Vertical Slice`
7. Подключить доступ и оплату → `Payment-ready Build`
8. Запустить и получить сигнал → `Launch Pack`

## Definition of Done этапа

Этап завершается, только если:

1. принято обязательное решение;
2. добавлен требуемый артефакт;
3. пройдены все обязательные проверки;
4. нет нерешённого блокера.

## Текущий статус

Первый UX/UI-каркас работает на статических данных и хранит интерактивный прогресс только в состоянии браузера. Он специально не подключён к старым моделям Blueprint.

## Следующая техническая фаза

После UX-проверки:

1. утвердить терминологию и состав SaaS-маршрута;
2. спроектировать новую Prisma-модель с версионированием;
3. добавить `ProjectRun`, `OutcomeRun`, `ArtifactSubmission`, `CheckResult`;
4. сделать единый серверный расчёт прогресса;
5. подключить авторизацию и постоянное сохранение;
6. добавить новый пункт меню и заменить старый Blueprint только после готовности.
