## Главный принцип: «Маршрут уже спроектирован»

Пользователь приходит не проектировать разработку, а получить работающий продукт. ProektMap заранее принимает основные инженерные решения: выбирает стек, модели, программы, порядок действий, команды, промпты и критерии готовности.

Обещание продукта:

> **Мы уже спроектировали маршрут. Вам осталось пройти его.**

```text
Готовый результат
  → рекомендация ProektMap и причина
    → точное действие
      → готовая команда или промпт
        → наблюдаемый результат
          → следующий шаг
```

Пользователь не заполняет анкету, не пишет техническое задание с нуля, не обосновывает выбор и не сравнивает равноправные стеки. Альтернатива появляется только тогда, когда основной путь объективно не подходит.

## Decision-Driven Development → Guided Outcome Route

Мы строим не курс и не конструктор. Мы строим систему доведения до результата.

На каждом этапе `/resheniya`:

- **УВИДЕТЬ** — что сейчас строим;
- **ПРИНЯТЬ РЕКОМЕНДАЦИЮ** — ProektMap уже выбрал основной путь и объяснил причину;
- **ВЫПОЛНИТЬ** — сделать точные действия, скопировать команду или готовый промпт;
- **ПРОВЕРИТЬ** — получить наблюдаемый сигнал готовности;
- **ПРОДОЛЖИТЬ** — открыть следующий шаг.

Процент прогресса растёт только после проверки.

Decision-Driven Development остаётся внутренней работой ProektMap: команда заранее принимает и проверяет решения, чтобы не перекладывать проектирование на пользователя.

## Не школа — навигатор результата

ProektMap не учит программированию с нуля и не экзаменует пользователя. Он даёт готовый инженерный маршрут, помогает выполнить каждый шаг и ведёт к запуску.

## Экосистема Skills

Skills — переиспользуемые процедуры для человека и AI-агента.

### Два типа Skills

| | Prisma Skill | Agent Skill |
|---|---|---|
| **Для кого** | Человек (обучается) | AI-агент (выполняет) |
| **Что это** | Учебный модуль | Файл `SKILL.md` с процедурой |
| **Где живёт** | БД, `/admin/skills` | `.cursor/skills/`, `.reasonix/skills/` |
| **Пример** | «Настройка ESLint» | `resheniya-author`, `visual-content` |

### Skills для развития /resheniya

| Skill | Роль |
|-------|------|
| `resheniya-author` | Создаёт маршрут по шаблону |
| `resheniya-validator` | Автоматически блокирует отход от контракта |
| `resheniya-auditor` | Независимо проверяет до публикации |

Правило Cursor: `.cursor/rules/resheniya.mdc` (автоматически на `src/app/resheniya/**`).

Обязательный конвейер: `resheniya-author → resheniya-validator → resheniya-auditor → build → публикация`. Автор не может сам объявить маршрут эталонным.

### Система доверия

- **🟢 verified** — ручная проверка, нет доступа к secrets, протестирован
- **🟡 community** — новый Skill, ждёт аудита
- **🔴 flagged** — не использовать

Новые Skills создаются со статусом **community**.

Стратегия: русскоязычный навигатор по **проверенным** Skills (ЮKassa, Telegram, РФ-стек), не океан непроверенных файлов.

## 7 правил ProektMap

1. **Маршрут уже спроектирован.** Основной стек и порядок выбирает ProektMap.
2. **Понятный язык.** Объясняем как коллеге за кофе.
3. **Действие и сигнал.** Каждый шаг заканчивается наблюдаемым результатом, не «я прочитал».
4. **AI — инструмент, не замена.** Учим управлять AI.
5. **Реальный проект.** Не учебный пример, а твой продукт.
6. **Песочница — первый шаг.** Прежде чем строить — исследуй.
7. **/resheniya — центр результата.** Новые маршруты и агенты строят вокруг него.
