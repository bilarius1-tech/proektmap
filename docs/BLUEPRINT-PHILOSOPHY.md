# Философия перестройки Blueprint

## Главный принцип

Blueprint — не карта проекта. Blueprint — **операционная система запуска проекта**. Человек покупает не знания, а сокращение пути.

## Что внутри каждого этапа

| Элемент | Описание |
|---------|----------|
| Задача | Что конкретно делаем сегодня вечером |
| Результат | Что будет готово после этапа |
| Промпт | Реальный, скопировал → вставил → работает |
| Артефакты | Файлы которые создадутся (competitor-analysis.md) |
| Сущности БД | Поля, типы, связи |
| Навыки | +Prisma, +PostgreSQL |
| Термины | Кликабельные ссылки на глоссарий |
| Решения | Почему выбрали этот подход |
| Чек-лист | Как проверить что этап реально завершён |

## Что убрать

- Мотивационный текст
- «Вам следует подумать»
- «Рекомендуется рассмотреть»
- «Определите целевую аудиторию»
- Любую воду

## Приоритет улучшений

1. Реальные рабочие промпты
2. Сущности БД и архитектура данных
3. Навыки на каждом этапе
4. Интеграция с глоссарием
5. Удаление воды — обязательно для всех

## Формат промпта

Промпт должен быть конкретным:
- Ты [роль]. Сделай [задача].
- Используй [стек]
- Результат сохрани в [файл]
- Проверь что [чек-лист]

## Формат сущностей БД

User (id UUID PK, name string, email string unique, createdAt timestamp)
Order (id UUID PK, userId FK, status enum, total number)

## Связь с монетизацией

Бесплатный Blueprint показывает структуру.
Премиум Blueprint показывает реальные промпты + сущности БД.

## Продукт для выполнения, а не для чтения

Плохой Blueprint = ценность 0 руб. Хороший Blueprint = деньги.

### Плохой Blueprint
- «Авторизация является важным компонентом»
- «Рекомендуется использовать современные технологии»
- Нет промпта, нет сущностей, нет чек-листа

### Хороший Blueprint (за который платят)
- Цель: Пользователь может войти через Telegram
- Промпт: готовый, скопировал — вставил
- Сущности: User, TelegramAccount, Session
- Навыки: JWT, OAuth, Cookies
- Термины: JWT, OAuth, Session
- Чек-лист: пользователь вошёл, сессия создаётся, выход работает

## Новая структура этапа

Каждый этап обязан содержать:
- Цель — что делаем
- Промпт — готовый, для AI-агента
- Артефакт — что создастся (файлы, таблицы)
- Сущности БД — поля, типы, связи
- Навыки — что прокачивается
- Термины — ссылки на глоссарий
- Чек-лист — как проверить что готово

## Метрика качества Blueprint

Blueprint Completeness — процент заполнения:
- Промпты: цель 100%
- Навыки: цель 100%
- Термины: цель 100%
- Сущности БД: цель 80%+
- Чек-листы: цель 80%+

## Правило завершённости этапа

Этап считается незавершённым если нет:
- 1 реального промпта
- 1 ожидаемого результата
- 1 навыка
- 1 термина из глоссария

## Для продаж

Продавать не «Как сделать CRM», а «Готовая CRM Blueprint»:
- 120 промптов
- 34 сущности БД
- 57 навыков
- 200 терминов
- 80 решений
- Чек-листы проверки

Blueprint = товар, а не контент.
