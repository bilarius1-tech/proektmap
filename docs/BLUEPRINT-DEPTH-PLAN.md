# Стратегический план: как сделать Blueprint глубоким и полезным

Дата: 3 августа 2026
Цель: Каждый Blueprint должен давать пользователю не поверхностное знание, а глубокое понимание — что делать, почему именно так, и как применить в реальном проекте.

================================================================================
## Раздел 1. Главная проблема сегодняшних Blueprint'ов
================================================================================

### 1.1. Симптомы поверхностности
Пользователь проходит Blueprint и получает:
- Общую информацию вместо конкретики
- Промпты-заглушки вместо рабочих шаблонов
- Список вариантов без объяснения «почему рекомендуем именно это»
- Нет связи между решениями
- Нет ощущения прогресса

### 1.2. Корневая причина
Blueprint сейчас = справочник тем. А должен быть = путеводитель по реальному проекту.

### 1.3. Что должен чувствовать пользователь
ДО: «Я не знаю с чего начать, страшно что-то упустить»
ПОСЛЕ: «Я знаю весь путь от идеи до запуска, у меня есть бриф со всеми решениями, я могу передать его AI и получить рабочий проект»

================================================================================
## Раздел 2. Принципы глубокого Blueprint'а
================================================================================

### Принцип 1. Один Blueprint = один реальный проект
Не абстрактный курс, а конкретный путь создания конкретного продукта.

### Принцип 2. Каждое решение имеет последствия
Связи явно: «Ты выбрал Next.js → SSR из коробки → SEO проще → но нужен Node-хостинг»

### Принцип 3. Три уровня глубины в каждом решении
- Уровень 1 — ПОНИМАНИЕ (30 сек): Что это? Зачем? Что будет если проигнорировать?
- Уровень 2 — ВЫБОР (2-5 мин): Варианты, рекомендация, что НЕ делать
- Уровень 3 — ДЕЙСТВИЕ (5-15 мин): Шаги, промпт для AI, чек-лист проверки

### Принцип 4. Реальный промпт, а не шаблон-заглушка
Конкретный, контекстный, копируемый, проверяемый.

### Принцип 5. Фиксация = основа брифа
Каждое решение записывается в бриф. На выходе — готовый документ для AI.

### Принцип 6. Прогресс виден и ощутим
Шкала 0→100%, XP, бриф растёт, навыки прокачиваются.

================================================================================
## Раздел 3. Структура идеального решения (12 полей)
================================================================================

1. **problem** — ЧТО решаем. Одно предложение.
2. **why** — Последствия игнорирования / неправильного выбора.
3. **context** — Что AI должен знать о проекте.
4. **constraints** — Что НЕ делать. Жёсткие рамки.
5. **recommended** — Рекомендация с обоснованием.
6. **content** — Пошаговая инструкция.
7. **tradeoffs** — Компромиссы.
8. **whenNotUse** — Когда рекомендация НЕ работает.
9. **mistakes** — Типичные ошибки новичков.
10. **validation** — Чек-лист «всё работает».
11. **iteration** — Что улучшить после базовой настройки.
12. **promptTemplate** — Рабочий копируемый промпт.

================================================================================
## Раздел 4. Связи между решениями
================================================================================

Каждое решение знает о предыдущих. В context подставляются предыдущие решения.

Визуализация (React Flow):
- Зелёная стрелка — усиливает (Next.js → SSR → SEO)
- Красная стрелка — конфликт (Next.js → Node-хостинг, не PHP)
- Жёлтая стрелка — компромисс (Vercel → быстро, но vendor lock-in)

================================================================================
## Раздел 5. Чек-лист качества (20 пунктов)
================================================================================

### Содержание (8)
[ ] Все 12 полей заполнены в каждом решении
[ ] Нет демо-заглушек
[ ] Промпты рабочие и конкретные
[ ] Рекомендации с обоснованием
[ ] Ошибки из реальной практики
[ ] Валидация с проверяемыми пунктами
[ ] Контекст учитывает тип проекта
[ ] Связи с другими решениями указаны

### Структура (5)
[ ] Стадии в логическом порядке
[ ] 5-8 решений на стадию
[ ] 30-50 решений всего
[ ] XP пропорционально сложности
[ ] Порядок учитывает зависимости

### UX (7)
[ ] Прогресс виден на каждом шаге
[ ] Решения можно пропустить
[ ] Бриф формируется динамически
[ ] SkillChips в 80%+ решений
[ ] Термины глоссария в текстах
[ ] Мобильная версия читаема
[ ] Время на решение указано

================================================================================
## Раздел 6. План заполнения
================================================================================

### Приоритеты
1. Аудит активных: corporate-website (40), saas-project (21), game-dev (19)
2. Заполнить пустые: mobile-app, photo-service, api-service (по 25-30)
3. Новые: telegram-bot (20-25), ai-chatbot (25-30), landing-page (15-20)

### Единая структура стадий
1. Исследование (5-7) — цель, аудитория, конкуренты, монетизация
2. Контент (4-6) — структура, контент-стратегия, SEO-семантика
3. Бизнес-логика (4-6) — роли, user flows, интеграции, безопасность
4. Инфраструктура (4-6) — домен, хостинг, БД, CI/CD
5. Технологии (5-7) — фреймворк, UI, авторизация, AI
6. Разработка (5-8) — структура, компоненты, API, тесты
7. Запуск (3-5) — деплой, аналитика, SEO, маркетинг
8. Развитие (2-4) — масштабирование, итерации

================================================================================
## Раздел 7. Метрики качества
================================================================================
- Заполненность: 100% решений с 12/12 полями
- Конкретность промптов: 90%+ с версиями и файлами
- Связанность: 70%+ со ссылками на другие решения
- Завершаемость: 30%+ пользователей доходят до конца
- Время на решение: 5-15 минут
- Конверсия в бриф: 50%+

================================================================================
## Раздел 8. Итоговая формула
================================================================================

Глубокий Blueprint =
  Реальный проект (не абстрактный)
+ Пошаговый путь (не список тем)
+ 12 полей в каждом решении (не 3-4)
+ Рабочие промпты (не заглушки)
+ Связи между решениями (не изоляция)
+ Видимый прогресс (не «прочитал и забыл»)
+ Бриф на выходе (не «молодец, прошел»)
+ Навыки и XP (не просто «галочка»)
