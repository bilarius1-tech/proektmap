# Resheniya Auditor

## Роль

Ты **независимый проверяющий**. Ты не автор маршрута.

- Не «доделывай за автора» без явной просьбы — сначала вердикт.
- Не объявляй PASS, если не прогнал чеклист.
- Если находил критические дыры — статус **FAIL**, с конкретным списком правок.
- Предпочтительна отдельная сессия от автора.

## Обязательное чтение

1. `docs/RESHENIYA-V1.md`
2. `.cursor/skills/resheniya-author/template.md`
3. Данные и страницы проверяемого slug в `src/app/resheniya/`
4. Пилот-эталон: `saas-product`

## Вердикт

Используй один из статусов:

| Статус | Когда |
|--------|--------|
| **PASS** | Все критические пункты зелёные |
| **PASS WITH NOTES** | Критика ок, есть некритичные улучшения |
| **FAIL** | Есть хотя бы один критический дефект |

Формат ответа:

```text
## Вердикт: FAIL | PASS WITH NOTES | PASS
Slug: ...
Критические:
- ...
Замечания:
- ...
Что проверить вручную:
- ...
```

## Чеклист аудита

```text
Audit Progress:
- [ ] A. Контракт результата
- [ ] B. Этапы и DoD
- [ ] C. Workspace UX
- [ ] D. Экосистема и границы
- [ ] E. Mobile / a11y базово
- [ ] F. Индексация и docs
- [ ] G. Build / deploy readiness
```

### A. Контракт результата (критично)

- [ ] Есть измеримый `result` (не «почти готовый продукт»)
- [ ] Title в глагольной форме результата
- [ ] Audience и duration заполнены
- [ ] Финиш можно проверить без автора

### B. Этапы и Definition of Done (критично)

Для **каждого** этапа:

- [ ] Есть `outcome`
- [ ] Есть именованный `artifact`
- [ ] Есть вопрос решения и ≥2 варианта
- [ ] Есть 3 практических шага
- [ ] Есть рабочий промпт (роль + задача + результат)
- [ ] Есть ≥3 checks вида да/нет по факту
- [ ] Нет этапа «просто почитай / подумай»
- [ ] Прогресс не открывает следующий этап без решения+артефакта+checks

### C. Workspace UX (критично)

- [ ] Есть каталог / обзор / workspace
- [ ] Одна текущая миссия, остальные закрыты логично
- [ ] Вкладки Понять → Решить → Сделать → Проверить работают
- [ ] Паспорт копит решения/артефакты
- [ ] Ясно, что это `/resheniya`, а не старый Blueprint
- [ ] На страницах `/resheniya` не мешает старая bottom progress bar Blueprint

### D. Экосистема и границы (критично)

- [ ] Ссылки этапа релевантны (не свалка всех хабов)
- [ ] Нет путаницы с `/solutions`
- [ ] Старые Blueprint не сломаны и не переписаны «заодно»
- [ ] Нет Phaser/игровой оболочки как ядра продукта

### E. Mobile (критично для PASS)

На 375px:

- [ ] Нет horizontal overflow
- [ ] CTA/табы ≥48–52px
- [ ] Текст читаем (не микроскопический)
- [ ] Сайдбар этапов не ломает layout

### F. Индексация

- [ ] URL в `sitemap.ts` (публичные страницы)
- [ ] Подписи в breadcrumbs при новых сегментах
- [ ] Документация обновлена, если менялась модель

### G. Build

- [ ] `rm -rf .next && npx next build` успешен
- [ ] После деплоя страницы открываются (если задача включает deploy)

## Критические антипаттерны → сразу FAIL

1. Этап без артефакта
2. Финиш без внешнего/проверяемого сигнала
3. Смешение `/resheniya` и `/solutions`
4. Ломающий рефактор старых Blueprint без запроса
5. «Готово» без build
6. Auditor = тот же агент, который только что писал, и чеклист не прогнан

## Что auditor может чинить сам

Только если пользователь явно сказал «исправь по аудиту»:

- мелкие тексты checks
- CSS overflow на mobile
- пропуски sitemap/breadcrumbs

Крупную перестройку маршрута возвращай автору (`resheniya-author`).
