# Правила разработки с AI-агентами

Полный текст правил. Версия для страницы /agent-engineering/rules на proektmap.ru.

---

## Старт — это не «сделай классный SaaS»

Плохой старт: написать агенту «сделай классный SaaS-проект» и ждать. Такой
промпт — гарантированный бардак: агент угадывает, выдумывает, прыгает и теряет
контекст.

Правильный старт: **скачать шаблон → положить идею в `inputs/idea.md` → идти
по 8 фазам**. Шаблон даёт агенту закон (AGENTS.md), команды-фазы и заготовки
документов. Идея даёт цель. Фазы не дают прыгнуть к коду раньше времени.

---

## Кодекс AI-агента (7 правил)

1. **Сначала читай AGENTS.md** — правила проекта важнее общих привычек модели.
2. **Одна линия истории в git** — работай в `main`, не оставляй ветки разъехавшимися.
3. **Инкременты** — один шаг = код + проверка + коммит. Никаких «сделаю всё сразу».
4. **Не выдумывай** — нет данных → спроси или `[уточнить: …]`.
5. **Scratch вне репозитория** — пробы и мусор не коммитим.
6. **Не разрушай данные** — без force-reset БД, без удаления прода.
7. **Проверяй сам себя** — после каждого шага тест/билд, перед финалом — дифф.

| # | Фаза | Команда | Вход | Выход | Критерий готовности |
|---|---|---|---|---|---|
| 0 | Идея | — | голова пользователя | `inputs/idea.md` | Идея записана своими словами |

## Дизайн: скиллы Anthropic + Emil Kowalski

Перед кодом агент задаёт визуальный язык. В шаблоне четыре скилла:

| Скилл | Источник | Что даёт |
|---|---|---|
| **web-design-guidelines** | Anthropic | Правила продакшн-интерфейсов: типографика, цвет 60-30-10, сетка 4/8px, состояния, запреты «AI-скуфа» |
| **taste-skill** | Anthropic | Вкус: сравнивать 2–3 варианта, выбирать по характеру/иерархии/ритму, обосновывать без слова «красиво» |
| **impeccable** | Anthropic | Безупречная полировка: выравнивание, контраст, пустые состояния, микрокопия, переходы 150–250 мс |
| **Adding Product Design** | Emil Kowalski | Продакт-дизайн для инженеров: дизайн как система, качество = сумма деталей, меньше но лучше |

## Правила окружения

- **git:** `git init`, ветка `main`, `.gitignore` (node_modules, .env, .next, dist, логи).
- **Стек по типу проекта:** SaaS/веб → Next.js + TypeScript; лендинг → Vite (или Next.js); Telegram-бот → Node.js + grammY.
- **Секреты:** `.env.example` в git, реальный `.env` — никогда.
- **Качество:** lint/format/test командами; всё проверяемое — команда (`npm run build`, `npm test`).
- **README:** как запустить, собрать и проверить — до начала разработки.

## Стартовый шаблон: анатомия

```
ai-project-starter/
├── README.md            ← как начать за 3 шага
├── AGENTS.md            ← кодекс агента (закон проекта)
├── inputs/idea.md       ← сырая идея пользователя
├── commands/            ← 8 команд-фаз (агент запускает по очереди)
│   ├── 00-brief.md      ← интервью: ЦА, боль, монетизация
│   ├── 01-research.md   ← конкурентный анализ в вебе
│   ├── 02-prd.md        ← одностраничный PRD
│   ├── 03-design.md     ← визуальный язык по дизайн-скиллам
│   ├── 04-setup.md      ← окружение: git, стек, .env, README
│   ├── 05-plan.md       ← PRD → план работ
│   ├── 06-build.md      ← код инкрементами (шаг → проверка → коммит)
│   └── 07-review.md     ← самопроверка диффа и сдача
├── skills/              ← дизайн-скиллы (4 шт.)
├── templates/           ← заготовки: бриф, PRD, план
├── outputs/             ← результаты фаз
├── adapters/            ← команды в формате OpenCode / Cursor / Reasonix
└── docs/rules.md        ← этот текст
```

Каждый файл отвечает на три вопроса: **что это → зачем → когда трогать**.

## Чек-лист приёмки

- [ ] Проект запускается с нуля: clone → установка → `npm run dev`.
- [ ] `npm run build` проходит без ошибок.
- [ ] В диффе нет мусора, секретов и node_modules.
- [ ] Каждый шаг плана закрыт коммитом с понятным сообщением.
- [ ] README описывает запуск, сборку и проверку.
- [ ] Интерфейс соответствует UI-киту (не «примерно похоже»).
