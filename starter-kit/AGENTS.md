# AGENTS.md — закон проекта (читай до начала работы)

Этот файл — закон для AI-агента. Он работает в OpenCode, Cursor, Reasonix и
любой другой среде, которая умеет читать AGENTS.md. Правила в нём важнее
общих привычек модели.

## Как устроен этот проект

```
inputs/idea.md        ← сырая идея пользователя (точка входа)
commands/             ← 8 команд-фаз: brief → research → prd → design → setup → plan → build → review
templates/            ← заготовки документов (бриф, PRD, план)
outputs/              ← результаты фаз: brief.md, research.md, prd.md, ui-kit.md, plan.md, review.md
skills/               ← дизайн-скиллы (читаются на фазе design)
docs/rules.md         ← полный текст правил разработки
adapters/             ← копии команд под конкретную среду (opencode / cursor / reasonix)
```

## Главные правила (всегда)

1. **Иди по фазам.** Не прыгай сразу к коду. Порядок:
   `00-brief` → `01-research` → `02-prd` → `03-design` → `04-setup` →
   `05-plan` → `06-build` → `07-review`.
2. **Не выдумывай.** Нет данных — спроси пользователя или оставь
   `[уточнить: что именно]`. Не заполняй пробелы фантазией.
3. **Инкременты.** Один шаг = код + проверка + коммит. Никаких
   «сделаю всё сразу и потом покажу».
4. **Проверяй сам себя.** После каждого шага: тест, билд или явная проверка.
   Перед финалом — читай свой дифф.
5. **Не разрушай данные.** Без force-reset БД, без удаления веток/прода,
   без перезаписи пользовательских файлов без явного согласия.
6. **Scratch — вне репозитория.** Пробы, временные скрипты и сгенерированный
   мусор не коммитим; работай во временной папке и убирай за собой.
7. **Секреты — только в `.env`.** `.env` в `.gitignore`. В промптах, коде и
   коммитах секретов быть не должно.

## Git

- Рабочая ветка — `main`. Перед работой: `git pull`.
- Коммит после каждого шага плана, сообщение — что сделано и зачем.
- Если в проекте есть `master`, держи `main` и `master` на одном коммите.
- Перед финальной сдачей: `git status` чистый, в диффе нет мусора.

## Дизайн

- На фазе `03-design` обязательно прочитай `skills/`:
  `web-design-guidelines.md`, `taste-skill.md`, `impeccable.md`,
  `product-design-emil-kowalski.md`.
- Без UI-кита (палитра, типографика, отступы, тон) не пиши интерфейсы.

## Стоп-правила

- Пользователь сказал «стоп» → остановился и показал, что сделано.
- План расходится с реальностью → остановись и уточни, а не «доделывай как понял».
- 3 неудачные попытки одного шага → стоп + отчёт, не крутись по кругу.
