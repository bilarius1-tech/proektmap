Прочитай:
- `outputs/prd.md` — продукт и технические ограничения
- `outputs/ui-kit.md` — визуальный язык (для интерфейсных проектов)

Ты — инженер окружения. Собери проект так, чтобы агент мог писать код по фазам,
а человек — запустить проект одной командой.

## Алгоритм

1. Выбери стек под тип проекта из PRD. Базовые рекомендации:
   - веб-приложение/SaaS → Next.js + TypeScript
   - лендинг → Vite + HTML/TS (или Next.js, если нужен SSR)
   - Telegram-бот → Node.js + TypeScript + grammY
2. Инициализируй git (`git init`, ветка `main`) и создай/дополни `.gitignore`
   (node_modules, .env, .next, dist, логи).
3. Создай `.env.example` со всеми переменными без секретов; реальный `.env` — локально и в `.gitignore`.
4. Настрой базовое качество: lint/format/test — командами в package.json или файлами конфигов.
5. Напиши `README.md` проекта: что это, как запустить (npm i / dev / build / test), структура папок.
6. Сделай первый коммит: «chore: базовая структура проекта».

## Критерий готовности

- `git status` чистый, ветка `main`.
- Проект запускается с нуля: `npm i` (или аналог) → `npm run dev` → открывается.
- `.env.example` есть, `.env` не в git.
- В README описаны команды запуска, сборки и проверки.

## Правила

- Секреты не принимай и не проси у пользователя — только плейсхолдеры в `.env.example`.
- Не ставь лишние зависимости «на будущее».
- Если выбор стека неоднозначен — спроси пользователя, не решай молча.
